# Experimentation Engine — Known Gaps

Honest list of what's missing or incomplete, as of this writing.

## Specified gaps

- **Real execution isn't wired to Phase 10's Integration Layer.** That layer hasn't been merged to `master` yet, so nothing in the experimentation module can actually execute an experiment against a live ad platform or landing-page infrastructure. `AssignmentService`'s `user_level_randomization` strategy exists as a design/data structure only — it explicitly says so in its own `note` field (`"Requires ad platform or landing page infrastructure capable of true randomized split traffic — not yet implemented for any specific provider."`).
- **Phase 11's analytics engine doesn't exist yet.** `MetricRecord`/`AnalyticsSnapshot` models exist, but nothing in the codebase writes to them. `BaselineService.calculateBaseline` and `MeasurementService.measureExperimentArm` both have real, working query logic against these models — but every real call today falls through to the `source: "no_data_available"` placeholder path because there's no data to find. This isn't a bug in either service; it's an honest reflection of no upstream producer existing yet.
- **Autonomy/risk classification exists but is never enforced.** `AutonomyPolicyService.classifyExperimentRisk` correctly labels experiments `low`/`medium`/`high` risk, but `requiresApproval` is hardcoded `true` in every branch, and `ExperimentEngine.approveExperiment` doesn't call this service at all — approval is unconditionally human-gated regardless of what risk classification would say. There is no `OrganizationSettings` field for an org to opt into auto-approving low-risk experiments, and none was speculatively added.
- **No MongoDB Vector Search / RAG for learning retrieval.** `MarketingMemoryService.findRelatedLearnings` uses plain Mongoose queries (channel/contentType/independent-variable matching, joined in application code) rather than semantic/vector search. This is a deliberate, reasonable choice at current scale — there's no large corpus of learnings yet to justify the added complexity — but it means retrieval is exact-match on structured fields, not similarity-based.

## Additional gaps found while writing this documentation

- **Most services aren't wired into the live pipeline at all**, not just the two data-reading ones above. `VariantGeneratorService`, `AssignmentService`, `BusinessEvaluationService`, `MarketingMemoryService`, `StrategyHandoffService`, and `HypothesisGeneratorService` are all real, working code with no caller anywhere in `ExperimentEngine.js` or any controller — see `architecture.md`'s pipeline table and `services.md` for the full breakdown. Concretely: there's no REST endpoint to generate variant content, no endpoint to get a business-impact verdict, and `evaluateExperiment` never consults prior learnings before writing a new one (no contradiction/consistency check happens automatically).
- **`ExperimentationAgent` is registered but unreachable.** It's added to the agent registry (`registerAgents.js:16`), but nothing in the routes layer or orchestrator (`AgentSelector.js` is the only caller of `agentRegistry.getByCapability`, and no route drives it for experimentation) ever dispatches to it. It's dead code from the live API's perspective today.
- **`StrategyHandoffService` has a real validation gap, not just a missing wiring.** `Recommendation.type`'s enum doesn't include `"strategy"` as a value yet (only `content/campaign/budget/audience/creative/seo/conversion/channel/technical`). Calling `proposeStrategyChangeFromLearning` with `category: "strategy"` will fail Mongoose validation today — surfaced as `{success:false, error}`, not silently worked around, but still a real blocker until the enum is extended.
- **`ExperimentVariant` seeding has no endpoint.** `evaluateExperiment` requires pre-existing `control`/`variant` `ExperimentVariant` documents (`MISSING_EXPERIMENT_VARIANTS` otherwise), but the only code that creates them (`VariantGeneratorService.generateVariantContent`) isn't reachable via the REST API — so today, seeding them for a real evaluate call requires calling that service directly or inserting documents by hand.
- **Async route mounting is a real (if narrow) startup race.** `server.ts` mounts `experimentation.routes.js` via a `.then()` on a dynamic `import()`, after `app.listen()` is already scheduled. Requests to `/api/experimentation/*` arriving in that narrow window right after process start will 404 rather than queue.
- **Test suite untested end-to-end in this session.** See `testing.md` — blocked by MongoDB Atlas IP allowlist from this sandbox, and separately, whether Jest's dynamic `import()` of the ESM `.js` source files actually works under the current `ts-jest` config is unverified (execution never got that far).
