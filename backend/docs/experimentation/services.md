# Experimentation Engine — Services

All files under `backend/src/modules/experimentation/`. See `architecture.md` for how (and whether) each one is actually called by the live pipeline.

| File | What it does | Status | Wired into `ExperimentEngine.js`? |
|---|---|---|---|
| `ExperimentEngine.js` | Top-level orchestrator: `createHypothesis`, `createExperiment`, `approveExperiment`, `scheduleExperiment`, `startExperiment`, `cancelExperiment`, `evaluateExperiment`. The only module the REST API actually calls. | IMPLEMENTED | — (this is the orchestrator) |
| `ExperimentationAgent.js` | Agent-registry dispatcher (`run({action, params})`) wrapping `createHypothesis`/`createExperiment`/`evaluateExperiment`. Registered via `registerAgents.js`. | IMPLEMENTED | N/A — registered but not invoked by any route or orchestrator call today |
| `services/ExperimentDesignService.js` | Turns a Hypothesis + control/variant values into a concrete design object (primary metric, duration, success criteria, stopping conditions). Validates control ≠ variant. | IMPLEMENTED | Yes |
| `services/BaselineService.js` | Computes a metric's historical baseline by averaging `MetricRecord` documents over a lookback window. | IMPLEMENTED (query logic). **PLACEHOLDER** for its data-reading path — Phase 11's `MetricRecord`/`AnalyticsSnapshot` models exist but are confirmed to have no producer/writer anywhere in the codebase yet, so every real call returns `source: "no_data_available"` until that pipeline is built. | Yes |
| `services/VariantGeneratorService.js` | Generates a real `Content` + `CreativeBrief` document per experiment arm via the existing `TextEngine`, and links it into a new `ExperimentVariant`. | IMPLEMENTED | No |
| `services/AssignmentService.js` | Decides traffic-split strategy: `user_level_randomization` for advertising/landing-page experiments vs. `content_cohort` comparison for organic channels (which can't be randomized at the user level). Also validates cohort size. | IMPLEMENTED (pure functions) | No |
| `services/MeasurementService.js` | Reads a variant's real-world performance by joining its `contentId` against `MetricRecord`. | IMPLEMENTED (query logic). **PLACEHOLDER** for its data-reading path — same root cause as `BaselineService`: no `MetricRecord` producer exists yet. | No |
| `services/StatisticalEvaluationService.js` | Deterministic two-proportion z-test (`calculateSignificance`) and result-state classification (`determineResultState`). No LLM calls. | IMPLEMENTED | Yes |
| `services/LearningService.js` | Turns a completed experiment's statistical result into a persisted `AgentLearning`, with a qualitative confidence label derived from how many prior experiments tested the same variable/channel. | IMPLEMENTED | Yes |
| `services/BusinessEvaluationService.js` | Combines a statistical result with cost/revenue inputs into a `positive`/`neutral`/`negative` business verdict — a statistically significant win can still be judged not worth it if cost rose too much. | IMPLEMENTED (pure function) | No |
| `services/MarketingMemoryService.js` | `findRelatedLearnings` (queries prior `AgentLearning`s by channel/contentType/independent variable) and `assessEvidenceConsistency` (flags `mixed` evidence rather than assuming every new result agrees with prior ones). | IMPLEMENTED | No |
| `services/StrategyHandoffService.js` | `proposeStrategyChangeFromLearning` — creates a `Recommendation` from a sufficiently-confident (`confidence ≥ 0.7`) `AgentLearning`. Never writes to `Strategy`/`StrategyVersion` directly. | IMPLEMENTED, with a known gap: `Recommendation.type` enum doesn't yet include `"strategy"` as a value, so calling this with `category: "strategy"` fails Mongoose validation (surfaced as `{success:false, error}`, not a crash). | No |
| `services/AutonomyPolicyService.js` | `classifyExperimentRisk` — keyword-based risk classification (`low`/`medium`/`high`) for advertising and content experiments. `requiresApproval` is hardcoded `true` in every branch — there's no org-settings opt-in for auto-approving low-risk experiments. | IMPLEMENTED | No |
| `services/HypothesisGeneratorService.js` | `generateHypothesisFromFinding` — deterministic (non-LLM) translation of a structured `{metric, observation, possibleCause, ...}` finding into a persisted Hypothesis, for agent-sourced hypotheses. | IMPLEMENTED, but has no live caller — the intended caller (Phase 11's Analytics/Optimization agents) doesn't exist yet. | No |
